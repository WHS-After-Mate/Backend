WHS After Mate — 프론트가 백엔드 API 호출하는 예시

이 파일은 서버 코드(server/src)를 import하지 않는다 — 오직 fetch()로 HTTP 요청만 보낸다. Android 앱이 Retrofit으로 하는 일과 원리가 완전히 같다. 먼저 다른 터미널에서 npm run dev로 서버를 켜둔 상태여야 한다.

A. 회원가입 실험 (가입 → 자동 로그인)

전화번호 SMS 인증은 미구현으로 제외됐다(server/README.md TODO 참고) — 이메일/비밀번호/생년월일만으로 바로 가입된다.

C. 비밀번호 찾기 실험

이건 SMS와 달리 개발용 우회 모드가 없다 — POST /auth/password/reset-request를 누르면 Supabase가 실제로 메일을 발송한다. 그러니 위 A에서 실제 수신 가능한 이메일로 가입해둔 계정이어야 끝까지 테스트된다. 

(아직 실행 안 함)

메일함에서 링크를 열면 "사이트에 연결할 수 없음" 같은 에러 화면이 뜨는데 정상이다 (아직 이 주소를 받아줄 프론트가 없을 뿐). 그 화면의 주소창을 보면 #access_token=...&refresh_token=...&type=recovery 형태로 붙어있다. access_token= 뒤부터 &expires_at= 앞까지의 긴 문자열만 복사해서 아래 칸에 붙여넣는다.

D. 사후관리 질문(AI 답변) 실험

이 API는 로그인이 필요하다(Authorization: Bearer accessToken). 먼저 위 B에서 로그인 버튼을 눌러 accessToken을 받아둔 상태여야 아래 버튼이 동작한다. question에 통증/출혈 같은 위험 신호 단어를 넣으면 LLM 호출 없이 곧바로 expert_required로 차단되는 것도 함께 확인할 수 있다.
