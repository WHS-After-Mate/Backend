# 관리 추천용 사업장 데이터 정리 가이드

"관리 추천" 화면(지수님을 위한 관리 추천)에서 AI가 지어내지 않고, 실제 존재하는 시술/사업장 정보만 사용하도록 하기 위한 데이터 포맷입니다.

실제 데이터는 `app/src/main/assets/care_data/care_data.json` 에 채워주세요.

## 구조 (2026-08-08 업데이트: 카탈로그 하나로 통일)

처음엔 "고객이 받은 시술"과 "추천할 관리"를 분리해서 관리하려 했지만, 실제로는 **정리해둔 46개 시술 목록 자체가 추천 후보**이기도 해서 카탈로그를 하나(`procedures`)로 합쳤습니다.

- 고객의 최근 시술 이력도 `procedures`를 참조하고
- 추천 후보도 같은 `procedures` 안에서 고른다

즉 "울쎄라를 받은 고객에게, 같은 카탈로그 안에 있는 색소침착 개선 시술(예: 피코웨이)을 추천"하는 식입니다. 별도의 "관리 상품" 데이터를 새로 모을 필요는 없습니다.

## concernTags (관심목표) — 반드시 이 10개 값만 사용

`내 정보` 화면의 관심목표 칩과 동일해야 매칭이 됩니다. 새 값을 추가하려면 `MyInfoViewModel.java`의 `interestGoals`도 같이 수정해야 해요.

```
리프팅·탄력 / 모공·피지 관리 / 보습·장벽 강화 / 색소침착 개선 / 얼굴 윤곽·볼륨 / 제모 / 두피 관리
바디라인·체형 관리 / 붓기 케어 / 컨디션·대사 관리
```

## 필드 설명

### businesses (사업장 3곳)
| 필드 | 설명 |
|---|---|
| id | 다른 곳에서 참조할 고유 id (영문) |
| name | 화면에 노출되는 사업장명 |
| talkChannelLabel | "상담하기" 버튼에 노출될 이름 |
| talkChannelUrl | 카카오톡 채널 등 상담 연결 링크 (없으면 빈 문자열로 두고 나중에 채우기) |

### procedures (시술/관리 통합 카탈로그 — `care_procedure_template.xlsx`의 [시술] 시트 내용이 여기로 들어감)
| 필드 | 설명 |
|---|---|
| id | 고유 id |
| businessId | 어느 사업장의 시술인지 |
| name | 시술명 |
| categoryTags | 이 시술이 다루는 고민 영역. concernTags 중에서 선택 (엑셀에서 O 표시한 열들) |

### customerProcedureHistory (예시일 뿐, 실제로는 여기 넣지 않음)
이건 사업장 데이터가 아니라 **로그인한 고객 개인의 시술 이력**이라 이 파일에는 넣지 않습니다. 실제 서비스에서는 사업장 예약/시술 기록 DB에서 가져오게 될 데이터의 모양만 예시로 남겨뒀어요.

## 추천 로직은 이렇게 동작할 예정입니다

1. 고객이 체크한 concernTags(관심목표)를 가져온다
2. 고객의 최근 시술 이력에서 procedures 카탈로그를 매칭해 각 시술의 categoryTags를 확인한다
3. concernTags와 categoryTags가 겹치는 다른 procedures를 후보로 뽑는다 (이미 최근에 받은 것 자체는 제외)
4. 후보 중 우선순위(겹치는 concernTag 개수, 최근 시술과의 연관성 등)로 정렬해 1순위를 "가장 추천하는 관리"로 노출한다
5. "이 관리를 추천하는 이유"는 매칭된 concernTag 이름을 그대로 문장으로 풀어서 자동 생성한다 (예: "색소침착 개선에 도움이 돼요.") — 사업장별로 더 자연스러운 문구를 쓰고 싶다면 나중에 procedure별 커스텀 문구 필드를 추가하면 됨
6. AI(LLM)는 이 후보 선정 결과 위에서 "설명 문구를 자연스럽게 다듬는 역할"만 하고, 시술명/사업장명 같은 사실 정보는 항상 이 JSON에서만 가져온다 — LLM이 지어내지 않도록

## 아직 정해지지 않은 것 (백엔드/관리자 웹 설계 전에 결정 필요)

- **권장 시점(예: "2~3주 후")**: 지금은 시술 간 타이밍 규칙 데이터가 없습니다. 처음엔 없이 출시하고, 필요해지면 시술 페어별 규칙을 추가하는 방향을 추천합니다.
- **고객 시술 이력의 출처**: 각 사업장의 예약/시술 기록을 연동할지, 관리자 웹에서 직접 입력할지 아직 결정되지 않았습니다.

## 할 일
