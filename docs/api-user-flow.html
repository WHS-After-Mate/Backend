API 유저플로우

유저플로우 "사후관리 Q&A AI 일차별 업데이트"(v2)의 화면 흐름에, api-spec.md에 정의된 실제 API 호출을 매핑한 다이어그램. 어느 화면에서 어떤 엔드포인트가 호출되는지 순서대로 확인한다. 비밀번호 찾기/변경 흐름(v0.5)은 최종 와이어프레임 검토로 추가돼 구현 완료됐다.

GET (조회) POST (생성/실행) PATCH / PUT (수정)

흐름 다이어그램

5개 화면 섹션(인증 → 홈 → 사후관리 Q&A → My Care → 설정) 순서를 그대로 따른다. 실선은 화면 이동, 점선은 조건 분기(LLM 응답 상태)를 의미한다.

단계별 표

다이어그램과 동일한 순서를 표로 정리한 버전. 분기 조건과 비고를 함께 확인할 수 있다.

#화면 / 액션API 호출비고
0a전화번호 인증 (신규 회원)POST /auth/signup/verify-phone/request, POST /auth/signup/verify-phone/confirmSMS 코드 발송 → 확인, phoneVerifiedToken 발급
0b회원가입 (신규 회원)POST /auth/signup이메일/비밀번호 + 인증된 전화번호
1로그인 화면 (기존 회원)POST /auth/login이메일/비밀번호, accessToken+refreshToken 발급
1a비밀번호를 잊으셨나요? (v0.5)POST /auth/password/reset-request, POST /auth/password/reset-confirm이메일 입력 → 재설정 링크 발송 → 링크로 새 비밀번호 설정 후 로그인 화면으로 복귀
2홈 진입GET /home/summary사후관리 카드·이용권 요약·추천을 한 번에 로드
3사후관리 카드 클릭 → AI 사후관리 가이드GET /aftercare/daily-guide시술 경과 일차별 사후관리. 1일 1회 LLM 생성, 자정까지 캐시
4챗봇 Q&A 진입GET /aftercare/question-categories진입 경로 2곳: ① 가이드 페이지의 "더 궁금한 점?" ② 홈 화면의 "AI에게 물어보기" 버튼
5질문 입력 → 답변POST /aftercare/questionsstatus: answered / out_of_scope / expert_required 로 분기
6추천 상세 보기GET /recommendations/next-care/:id홈 카드에서 진입 시에만 호출
7My Care 캘린더 보기GET /care-records/calendar월별 시술 날짜 마커 표시
8캘린더 날짜 클릭 → 시술 내역GET /care-records?dateFrom=dateTo클릭한 날짜로 조회, 기존 필터 쿼리 재사용
9이력 목록GET /care-records필터 시 dateFrom/dateTo/partOfBody/brand 쿼리 추가
10관리 상세GET /care-records/:id캘린더·이력 두 경로 모두 이 화면으로 도착. 기본 사후관리 안내 포함
11관리 상세 → AI 사후관리 가이드GET /aftercare/daily-guide?careRecordId=:id상세 화면의 "AI 사후관리 가이드" 버튼, 3번 항목과 동일 화면
12이용권 목록 → 상세GET /memberships, GET /memberships/:id잔여 횟수는 목록 응답에 포함
13프로필 화면GET /profile—
14관심 목표 설정PUT /profile/interests추천 API의 basis: goal 입력값으로 사용됨
14a비밀번호 변경 (v0.5)POST /profile/password내 정보 화면. 현재 비밀번호 확인 후 변경
15알림 설정 조회 → 변경GET / PATCH /notifications/settings변경 필드만 전달
16로그아웃POST /auth/logout서버 측 refreshToken 무효화

공통 처리 (다이어그램 밖)

모든 API 호출 공통: accessToken 만료로 401 UNAUTHORIZED 수신 시 POST /auth/refresh로 재발급 후 원 요청 재시도. refresh마저 실패하면 로컬 세션을 지우고 로그인 화면으로 이동한다.
