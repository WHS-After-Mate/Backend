WHS After Mate — admin-web이 호출하는 Admin API 실험용 예시 페이지

이 파일은 실제 admin-web(별도 저장소) 프론트가 아니다 — server_admin API를 fetch()로 직접 눌러보기 위한 임시 테스트 페이지일 뿐이다. 서버 코드를 import하지 않고 오직 HTTP 요청만 보낸다. 먼저 다른 터미널에서 server_admin을 npm run dev로 켜둔 상태여야 한다(기본 포트 4100). G 단계(가입 연동 테스트)를 실행하려면 server(포트 4000)도 함께 켜져 있어야 한다.

A. 환자 등록 — POST /patients

실제 클리닉 데스크에서 환자가 처음 방문했을 때 입력하는 정보. 성공하면 서버가 환자번호(patientNo)를 자동 발급한다. 여기서 등록한 환자의 id는 아래 "현재 대상 환자"(C~F 단계용), patientNo는 G 단계(회원가입 연동 테스트)의 입력칸에 각각 자동으로 채워진다. 

(아직 실행 안 함)

현재 대상 환자 (아래 C~F 단계가 전부 이 값을 사용)

A에서 환자를 등록하면 자동으로 채워진다. 이미 등록해둔 다른 환자를 대상으로 C~F를 테스트하고 싶으면 B(환자 목록 조회) 응답의 id 필드 값을 여기 직접 붙여넣으면 된다 — patient_no(EMR-P-XXXXXX 형태의 환자번호)가 아니라 UUID 형태의 id다. patient_no는 아래 G 단계(실제 회원가입 연동 테스트)에서 따로 쓴다.

B. 환자 목록/검색 — GET /patients?search=

이름·전화번호·환자번호 부분일치 검색. 비워두면 전체 목록.

(아직 실행 안 함)

C. 환자 상세 조회 — GET /patients/:patientId

프로필 + 시술기록 + 이용권 + 발급된 인증코드 이력을 한 번에 반환한다. 위 "현재 대상 환자" 칸의 patientId를 사용한다.

(아직 실행 안 함)

D. 시술 기록 추가 — POST /patients/:patientId/care-records

위 "현재 대상 환자"의 patientId를 대상으로 추가한다. careType은 /aftercare/daily-guide가 검수 가이드를 찾는 매칭 키다. 현재 시드 데이터는 peeling/laser_toning 2종만 지원하므로, 나중에 이 환자로 가입해 daily-guide까지 테스트해보려면 둘 중 하나를 써야 한다.

E. 이용권 추가 — POST /patients/:patientId/memberships

위 "현재 대상 환자"의 patientId를 대상으로 추가한다.

F. 가입 인증코드 발급 — POST /patients/:patientId/signup-code

위 "현재 대상 환자"의 patientId로 발급한다. 24시간 유효. 실제 SMS는 발송하지 않고 응답에 코드가 그대로 담겨온다(admin-web 화면에 표시해 데스크에서 안내하는 방식). 발급된 코드는 아래 G 단계에 자동으로 채워진다. 

(아직 실행 안 함)

G. (연동 테스트) 발급된 코드로 실제 회원가입 — POST /auth/signup (server, 포트 4000)

여기부터는 server_admin이 아니라 고객용 server를 호출한다. 위 A~F에서 만든 환자번호+인증코드로 실제 앱 계정을 생성해, 시술기록/이용권이 care_records/memberships로 1회성 이관(claim)되는지까지 전체 흐름을 확인할 수 있다. 성공 후 같은 환자번호로 다시 이 버튼을 누르면 409 PATIENT_ALREADY_CLAIMED가 나는 것도 확인해볼 수 있다. 

(아직 실행 안 함)
